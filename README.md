# TIDEHOLD — 떠도는 섬 · 캠페인 개발판

방어시설을 배치한 부유섬으로 바다를 탐험하고, 적을 처치한 자원으로 다시 섬을 키우는 **Windows 로컬 실행판과 PC 브라우저판의 싱글플레이 3D 게임 개발판**입니다. Three.js로 작성되며, 로그인·API 키·외부 생성 서비스·별도 백엔드가 필요 없습니다. 모든 모델과 효과는 코드로 생성합니다.

RTS 이동 대형은 밀집 3m와 분산 12m를 선택합니다. 두 척 이상 선택하고 바다 위 대형 버튼을 전환한 뒤 이동·공격 이동·예약을 발행하세요. 넓은 간격은 범위 피해를 줄이지만 수리·방호 범위를 함께 고려해야 합니다. 이미 발행한 명령과 집중 공격·호위는 유지합니다.

엔딩 이후 새 **선단의 세 도크**에는 도크마다 측면 추적자2기가 배치됩니다.24m 안의 정비정·방호정을 우선 추적하고 함선 옆으로 돌아오므로 지원선 배치·요격·냉각 차단을 함께 고려하세요. 적을 클릭하면 실제 추적 대상을 확인할 수 있으며, 겹친 적은 같은 위치를 다시 클릭해 정보를 순환합니다. 기존 진행 중인 도크는 원래 편대를 유지하며, 새 도크의 활성 저장은 최신 실행판이 필요합니다.

현재 사용자 목표는 **스팀 출시를 목표로 한 완성도, 자동 저장, 기지 방어와 탐험, 개별 함대의 생산·선택·드래그·RTS 전투, 최소 20시간 이상 콘텐츠**입니다. 기존 원정과 섬 성장에 함대 전투를 추가하는 개발 중이며 **그 목표는 아직 완료되지 않았습니다**. 스팀 등록·공개 배포는 수행하지 않았습니다. 최신 개발 기준은 `DEVELOPMENT.md`, 실제 구현·검증 상태는 `CAMPAIGN_VALIDATION.md`를 확인하세요.

**적 클릭**으로 실제 내구도·장갑·사거리와 대응 방법을 확인하세요. 정보 확인은 적을 활성화하거나 선택 함대를 해제하지 않습니다. 확인한 적의 주황색 사거리와 현재 공격/예약한 선택 함선 수를 표시합니다. **선택 함대 집중 공격** 또는 **Shift+클릭 예약**으로 지휘하며, 처치·확보·다음 목표 전환 시 정보를 닫습니다. 함대가 없어도 시설 도구를 해제한 상태에서 적을 확인할 수 있습니다.

**해역 수호자도 가까운 함대에 반격**합니다. 붉은 예고는 준비를 시작한 위치에 고정되므로 전투선을 이동·분산해 피하세요. 비상 보호막과 격벽 보강 연구는 섬·함대·호위선에 함께 적용됩니다.

**방호정**은 완성 해도2개·5번째 해역·정상 조선소4단계에서 ◆220/정원3으로 생산합니다.10m 안의 다른 아군 함선·섬 물가·시설·구조선의 피해를22% 줄이며 강화마다 범위가0.5m 늘어납니다. 자신은 보호하지 않고 화력이 낮아 공격 함선과 동행시키는 편성이 필요합니다. 선택한 방호정의 청록색 원과 카드에서 실제 범위를 확인하세요.7번째 해역/함선3단계의 확산 방호는 범위+4m/경감16.5%/내구도·속도-10%,10번째 해역/함선5단계의 집중 방호는 경감28.6%/범위-3m/속도-15%를 선택합니다. 여러 방호정·보호막·방호탑은 가장 강한 경감만 적용합니다. 방호정 저장은 최신 함대 형식4 실행판이 필요하며 기존1~3은 그대로 이어집니다.

**방호 해수**는 같은 공세의 복구 해수·모체 앞에서 반경14m의 방호망을 유지합니다. 적 정보창의 실제 보호 여부·보호 수·엄호 대상과 청록색 방호 원을 보고, 방호 해수를 먼저 공격하거나 빠른 함대로 지원 적을 범위 밖으로 분리하세요. 피해35% 경감은 중첩되지 않으며 살아 있는 활성 방호 해수만 같은 거점의 적을 보호합니다.

**복구 해수·모체의 지원 상태**도 적 정보창에서 확인하세요. 복구 해수는 같은 공세의 교전 중인 부상 아군만 회복하며, 실제 초당 회복량과17m 안의 회복 대상 수를 표시합니다. 모체는 남은 증원 횟수와 준비 시간을 보여 줍니다. 냉각탑·충격 파동의 둔화 중에는 증원 준비가 멈추고 남은 시간부터 이어집니다. 탐험 봉쇄 포대의 연결 효과는 증원을 계속 차단합니다.

**같은 선종을 빠르게 선택**하려면 Q 선택 모드에서 아군 함선을 두 번 클릭하세요. 화면 안의 같은 선종을 고릅니다. 함대 카드의 이름을 **Ctrl+클릭**하거나 **Ctrl+Enter**로 선택하면 화면 밖까지 같은 선종 전체를 고릅니다. Shift를 함께 누르면 기존 선택에 추가하며 명령·예약·전대 편성은 유지됩니다.

**지원선을 전투선에 붙여 운용**하려면 Q로 함대를 선택한 뒤 아군 함선을 우클릭하거나 그 함선 카드의 **선택 함대로 이 배 호위**를 누르세요. 선택 함선은 대상 뒤를 따라가고, 지원선은 기존 수리 범위에 들어온 부상 아군을 수리합니다. 청록색 원과 경로로 호위 대상을 확인하세요. 호위는 기존 예약을 취소하며 **H**로 사수, **G**로 섬 호위로 바꿀 수 있습니다. 서로 따라가는 순환 호위는 막고, 대상이 사라지면 제자리를 사수합니다. Shift+아군 우클릭은 기존 이동 예약입니다.

**함대 탭 → 선택 함대의 자동 사격**에서 선종·개장에 맞는 우선순위를 고르세요. 가까운 적·지원 적·장갑 적·손상 적을 먼저 상대할 수 있고, **기본 대응**으로 기존 폭발·지원 적 우선으로 돌아갑니다. 선택한 공격 함선에만 적용하며 집중 공격·예약·호위 대상과 정비정 수리를 바꾸지 않습니다. 사수·호위는 발견 전 적을 먼저 공격하지 않고, 공격 이동은 기존처럼 교전을 시작합니다. 기존 함대 저장은 그대로 이어지며, 우선순위를 바꾼 새 형식3 저장은 최신 실행판에서 불러오세요.

**섬 정비 → 전체 시설 복구**는 개별 복구 비용의 합계와 복구 후 전력을 표시하고 손상·파괴 시설을 한 번에 복구합니다. 자원이나 전력이 부족하면 결제하지 않으며 필요한 시설을 개별 복구할 수 있습니다. 공세 사이·정박·안전한 현장에서 정비하며 생산물 수확과 섬·함대 수리는 따로 진행합니다. 큰 섬과 여러 성벽을 유지할 때 시설을 반복해서 선택하는 부담을 줄입니다.

함선 카드의 **개장**에서 선종별 두 장비와 표준 장비를 비교하세요. 첫 장비는 **5번째 해역·함선3단계**, 후반 장비는 **9번째 해역·함선5단계**에서 열립니다. 정상 조선소3단계와 섬34m 안의 정비가 필요합니다. 사거리·기동·방호·수리의 장점과 약점, 현재/변경 후의 실제 수치와 비용을 보고 선택할 수 있습니다. 교체는 손상 비율·현재 명령을 유지하며 비용은 환급하지 않습니다. 기존 저장은 그대로 이어갈 수 있고, 개장한 저장은 최신 실행판에서 불러오세요.

2026-10-10 마무리 이후 조작 오류 수정과 추가 개발을 재개했습니다. Windows 실행판은 **`Play-Tidehold-Desktop.cmd`**, 브라우저판은 **`Play-Tidehold.cmd`를 더블클릭**하세요. 기존 저장이 있으면 시작 화면에서 **이어하기**를 선택합니다.

독침 사수는 가까이 압박하면 물러나며 사격하고, 복구 해수는 같은 공세의 부상 아군을 따라갑니다. **캠페인 → 연구소**에서 현재 연구 효과·다음 단계 효과·필요 비용과 부족한 자료/자원·해도 조건을 확인할 수 있습니다. 연구 버튼은 키보드 포커스를 유지하고, 다음 연구가 막히면 가능한 연구 또는 보유 자료 표시로 포커스를 옮깁니다.

새로 발견하는 **24개 탐험 항로**는 해역별 지형·연결·수비 대형이 다릅니다. 중계기를 조사하면 연결된 수비대의 공격 피해가20% 줄고, 봉쇄 포대를 조사하면 연결된 모체의 증원이 멈춥니다. 해역 지도와 수비 안내에서 현재 효과를 확인하고 조사 순서를 선택하세요. 기존에 저장하거나 귀환 기록을 남긴 항로는 원래 좌표를 유지합니다.

**섬 정비 → 배치도에서 시설 선택**으로 강화 전후의 실제 무장·생산·연구·방호·함대 정원과 내구도를 비교할 수 있습니다. 연구와 현재 원정 효과를 포함하며 전력·자원 부족량, 파괴 시설의 복구 조건, 해역별 강화 한도를 표시합니다. 키보드로 강화하거나 우선 공격을 바꿔도 조작 포커스를 유지합니다.

새로 출항하는 **36개 기지 방어**는 해역마다 진입 방향과 적 편대가 다릅니다. **해역 → 이번 공세**와 미니맵에서 방향별 적 수·주공 방향·대응할 적을 확인하세요. 공세 사이에는 시설을 재배치하고 함대를 정비할 수 있습니다. 다음 공세에서 주공과 전술이 바뀌므로 한쪽만 방어하지 않도록 준비하세요. 기존 진행 중 저장은 원래 공세를 이어갑니다.

방어의 **해역** 화면에는 공세 사이의 **섬 현장 수리(35)·능력 재보급(75)**가 표시됩니다. 전투 중에는 사용할 수 없으며, 수리는 섬 내구도를 최대130 회복하고 재보급은 보호막·긴급 수리·파동을 각2회 보충합니다. **현재 적 편대**를 펼치면 살아 있는 적의 수·장갑·사거리·대응을 확인할 수 있습니다.

## 실행

### 처음 플레이할 때

1. 시작 화면의 **처음부터 시작 · 추천 조작으로**를 누르세요. 저장한 게임이 있으면 **저장한 항해 이어하기**를 선택하세요.
2. 오른쪽 **지금 할 일 안내**에서 박격포를 선택하고 배치도의 빈 타일에 건설하세요. 실제 자원 100을 사용합니다. 기존 연사포만으로 출항해도 됩니다.
3. **첫 임무 목록 보기** → 첫 임무 카드를 누르세요. WASD/방향키로 섬을 움직이면 사거리 안의 적을 무장이 자동 공격합니다. 현재 목표와 회수품 선택은 **해역** 탭에서 확인합니다.
4. 임무 후 돌아와 보상으로 섬을 확장하고 농장·연구·함대를 준비하세요. 농장은 **원정 목표를 확보할 때** 생산합니다. 농장을 선택한 뒤 **수확하기**로 자원을 회수하세요. 정박지에서 기다리는 동안에는 생산하지 않습니다. **P**로 일시정지, 상단 **?**로 조작 안내를 다시 볼 수 있습니다. 초기 두 임무 동안 진행에 맞는 안내가 표시됩니다.

자동 항해를 원하면 시작 화면에서 **목적지 선택**을 고르세요. **비교 훈련**은 자동 저장 캠페인과 별도의 짧은 실험입니다.

전투 뒤에는 **섬 정비 → 정비할 시설** 목록을 확인하세요. 파손된 시설의 복구 비용과 농장·어업장의 수확량이 표시됩니다. 목록에서 시설을 선택한 뒤 상세 화면의 **시설 복구** 또는 **수확하기**를 누르세요. 상단의 섬 내구도 수리는 개별 시설을 복구하지 않습니다.

함대를 선택한 뒤 **Shift+우클릭**으로 이동·공격을 최대 8개 예약할 수 있습니다. **X → Shift+우클릭**은 공격 이동을 예약합니다. 바다에 선택한 배의 경로와 목적지가 표시되고 함대 목록에 예약 수가 나옵니다. 일반 우클릭은 기존 예약을 교체하며 **H 사수·G 호위**는 예약을 취소합니다. 예약도 자동 저장됩니다. 잘못된 저장 파일을 불러오면 거부 이유가 자동 저장 안내와 별도로 유지됩니다.

해역의 **원정 포기 · 출항 전 상태로**는 현재 원정을 취소하는 버튼입니다. 확인창에서 계속하기/Esc를 누르면 진행을 유지하고, 포기를 확인하면 자원·시설·함대를 출항 전으로 복원합니다. 나중에 이어서 하려면 자동 저장된 상태로 종료하세요. 탐험 기록과 보상을 보존하는 정상 귀환은 **기록을 가지고 귀환**을 사용합니다.

### GitHub에서 받은 소스

이 저장소에는 게임 소스·테스트·라이선스·실행 안내가 포함됩니다. 개인 저장 파일, 개발용 검사 프로필, `node_modules/`, `dist/`, `release/`는 포함하지 않습니다. 처음 받은 소스는 Node.js 22.12 이상에서 다음 명령으로 준비하세요.

```powershell
git clone https://github.com/twospears2004-ship-it/floating.git
cd floating
npm ci
npm run build
npm run play
```

### Windows 실행 파일

**`Play-Tidehold-Desktop.cmd`를 더블클릭**하면 가장 최근 빌드한 Windows 실행판을 엽니다. `artifacts/desktop-package.json`의 `executable`에 실제 생성한 **TIDEHOLD.exe** 경로가 있고 해당 `release/<생성 시각>/TIDEHOLD-win32-x64/` 폴더에서 직접 실행해도 됩니다. 실행에는 별도 Node.js·브라우저 설치나 인터넷 연결이 필요 없습니다. 실행 파일과 함께 있는 `resources/`, DLL, 라이선스 등 **폴더 전체**를 보관하세요. F11은 전체 화면, Alt는 메뉴를 엽니다. Windows x64용 개발판이며 서명·Steam 등록·공개 배포는 수행하지 않았습니다.

실행판의 캠페인은 `%APPDATA%\TIDEHOLD\saves\campaign.json` 및 `campaign.backup.json`에 저장됩니다. 5초 자동 저장과 창 종료 직전 저장을 지원하고, 저장 실패 시 게임으로 돌아가거나 마지막 저장으로 종료할 수 있습니다. 브라우저 저장 캐시가 사라져도 정상 PC 파일을 불러오고, 손상된 기본 파일은 검증된 백업으로 복구합니다. 기존 웹판의 캠페인은 저장 파일 내보내기 → 실행판 불러오기로 옮깁니다.

소스에서 실행판을 다시 만들 때만 개발용 Node.js가 필요합니다. 정확한 Electron 44.7.0과 패키지 도구 20.3.0은 `package-lock.json`으로 고정했습니다. Electron 패키지 설치와 실행 바이너리 설치를 구분하며 다음 명령으로 프로젝트 내부에 캐시를 준비합니다.

```powershell
npm ci
$env:electron_config_cache = Join-Path (Get-Location) '.electron-cache'
npm run setup:desktop
npm run build:desktop
# 개발용 Electron에서 빌드된 게임 실행
npm run desktop
```

`npm run build:desktop`은 매번 별도 출시 폴더를 생성합니다. 현재 실행 파일의 SHA-256과 경로는 `artifacts/desktop-package.json`에 기록됩니다. 실행판의 내장 런타임은 Electron 44.7.0 / Chromium 152.0.7977.130 / Node.js 24.21.0입니다. PC 파일 저장·실제 종료·다시 실행·백업 복구·읽기 전용 파일·브라우저 캐시 쓰기 실패의 6개 흐름을 격리된 프로필에서 검사했습니다. 세부 증거는 `CAMPAIGN_VALIDATION.md`에 있습니다.

실행 폴더를 다른 PC로 옮길 ZIP은 빌드 후 `.\scripts\Archive-Desktop.ps1`로 만듭니다. `artifacts/desktop-archive.json`에 실제 ZIP 경로·크기·SHA-256을 기록합니다. 압축을 풀고 폴더 안의 `TIDEHOLD.exe`를 실행하며 개인 캠페인은 게임에서 내보내어 옮깁니다. 제작용 테스트 프로필은 ZIP에 포함하지 않습니다.

실행 폴더의 **`PLAY_GUIDE.md`**에는 첫 임무, 생산/강화, 실제 함대 단축키, 방어 진입 안내, 탐험 귀환과 저장 방법이 있습니다. 공유 ZIP에서도 같은 안내 파일을 확인할 수 있습니다.

## 첫 플레이

시작 화면의 기본 선택은 **새 캠페인**입니다. A/B 이동 방식을 선택하고 박격포를 배치한 뒤 **캠페인 → 표류자의 항로**를 선택해 출항하세요. 해역 탭에는 현재 목표가 표시됩니다. 확보한 회수품을 선택하고 다음 목표로 이동하세요. 교전 사이에는 현장 수리·능력 재보급·시설 재배치가 가능합니다. 임무가 끝나면 섬을 유지한 채 정박지에서 연구·강화하고 다음 원정을 준비합니다. 기존 짧은 원정은 **비교 훈련**을 먼저 고른 뒤 아래 흐름으로 플레이할 수 있습니다.

1. 시작 화면에서 **A 실시간 조종** 또는 **B 목적지 선택**을 고릅니다.
2. **박격포**를 누르고 섬의 북쪽 빈 타일에 배치하세요. 오른쪽 배치도 또는 3D 타일을 클릭할 수 있습니다. 초기 연사포를 선택해 강화하는 출발도 가능합니다.
3. **탐험 항로 → 산호 여울**을 선택합니다. A에서는 항로 표시 후 직접 이동하고, B에서는 자동 출항합니다.
4. 사거리 안의 적을 자동 공격합니다. 두 포식자를 처치하면 총 자원 **100**을 받습니다.
5. 연사포를 강화하고 섬을 확장한 다음 **버려진 포대**에 도전하세요. 마지막 **검푸른 해구**는 추가 무장·수리를 준비해 도전하세요.

시설을 선택하면 황금빛 원으로 실제 사거리를 표시합니다. 무료 재배치와 투자 금액의 60%를 회수하는 철거가 가능합니다. 전투·자동 항해 중에는 정비가 잠깁니다. 캠페인 목표 확보 후에는 **현장 정비 · 출항 준비** 상태가 유지됩니다. 정비를 마친 뒤 항로 버튼을 누르거나 A에서 직접 이동하면 다음 교전이 시작됩니다.

## 조작

설정·도움말·일시정지 등의 대화상자에서는 Tab/Shift+Tab으로 안쪽 항목을 순환합니다. 설정의 음량·화질 입력에서도 Esc로 닫을 수 있습니다. 새 캠페인 확인창의 Esc는 취소하며 기존 저장을 유지합니다.

| 행동 | 조작 |
|---|---|
| A 모드 이동 | WASD 또는 방향키. W/↑는 지도 북쪽. 한글 입력 상태에서도 동작하며 정박지에서도 이동 가능 |
| B 모드 이동 | 탐험 항로의 출항 버튼. 교전 중 직접 이동 불가 |
| 건설·확장 | 시설/확장 버튼 → 3D 타일 또는 오른쪽 배치도 클릭 |
| 시설 선택 | 3D 섬의 기존 시설 타일 클릭 |
| 함대 선택 모드 | Q 또는 함대 선택 버튼. 클릭·드래그로 선택, Shift 추가 선택 |
| 유닛 이동·공격 | 선택 모드에서 바다·적을 우클릭. X를 누른 뒤 우클릭은 공격 이동 |
| 유닛 편대 명령 | F 전체 선택, H 위치 사수, G 섬 호위 |
| 함대 시점 | C 또는 함대 시점 버튼. 지도 클릭으로 먼 곳을 확인 |
| 확대·축소 | 3D 화면에서 마우스 휠 |
| 시점 회전 | 마우스 오른쪽 드래그. 함대 선택 모드에서는 Alt+오른쪽 드래그 또는 가운데 버튼 드래그 |
| 일시정지 | P 또는 상단 Ⅱ. Esc는 배치 취소 후 일시정지 |
| 조작 안내 | 상단 ? |
| 초기화 | 상단 다시 시작 / 패배·승리 화면의 재도전 |
| 모드 비교 | 화면 하단 이동 방식 비교 → 다른 모드 선택 |

비교 훈련은 초기화·모드 변경·새로고침 시 새 원정을 시작합니다. **캠페인은 5초마다 자동 저장**하며 이어하기는 일시정지 상태로 복원합니다. 캠페인의 이동 방식 변경은 현재 섬과 진행을 유지합니다. 새 캠페인은 기존 저장을 교체하기 전에 확인 화면을 보여 줍니다. 창이 포커스를 잃거나 탭이 숨겨지면 자동 일시정지합니다. UI 버튼에 포커스가 있을 때 방향키는 섬을 움직이지 않습니다. 이동 모드의 재미는 플레이 후 판단할 비교 대상입니다.

- 섬에 직접 건설하는 회수 크레인·해상 어업장·수경 농장·해상 연구소. 가까운 적 잔해의 추가 회수, 가장자리 항해 어획, 목표 확보에 따른 작물 성장, 새 목표 유형의 조사로 성장합니다. 생산 시설을 선택해 **수확하기**로 자원을 확보하며 강화하면 효율이 증가합니다. 공간·전력은 무장과 공유합니다. 정박만으로 자원이 생기는 대기 시스템은 없습니다.

## 테스트

현재 소스와 검사 파일을 고정 복사해 별도 포트에서 전체 검사를 실행하려면 `node scripts/full-ui-check.mjs`를 사용합니다. 기존 `node_modules`와 정상 모델 검사로 만든 `artifacts/campaign-fixtures`, `colony-fixtures`, `exploration-fixtures`, `atlas-fixtures`, `defense-fixtures`가 필요합니다. 없으면 아래 캠페인·생산·탐험 검사와 `npm run audit:atlas`, `node scripts/audit-defense.mjs --only=defense-black-1`로 먼저 준비하세요. 결과와 복사본은 고유 `artifacts/full-ui-<시각>/`에 저장됩니다. 실제 시간 장기 검사와 개인 저장은 공유하지 않으며 UI 가상 시간은 플레이 시간 증거로 합산하지 않습니다.

```powershell
npm test
npm run test:browser
npm run audit:campaign
npm run audit:colony
npm run audit:exploration
npm run audit:journey
# 중단된 연속 검사의 마지막 완료 저장에서 재개
node scripts/audit-journey.mjs --resume
```

`npm test`는 Node 내장 테스트 러너입니다. `npm run test:browser`는 Playwright로 **설치된 Chrome을 새 테스트 프로필에서** 실행합니다. 개발 서버가 없으면 자동으로 시작합니다. Chrome이 없는 환경은 다음처럼 프로젝트 안에 Chromium을 준비할 수 있습니다.

전체 브라우저 명령은 먼저 정상 모델 행동으로 보스 직전 저장, 생산 구성의 해역별 저장, 탐험 시작 저장과 후반 방어 완료 저장을 생성하고 모든 UI 흐름을 실행합니다. 기존 핵심 UI만 확인하려면 `npm run test:browser:core`, 보스만 확인하려면 `npm run test:bosses`를 사용하세요. `npm run audit:campaign`은 방어/범위 조합·연사포 집중·관통포 집중 전략을 비교해 `artifacts/`에 기록합니다. 실제 물가에 맞춘 무장 재배치와 다음 목표 방향의 방호 시설 재배치도 정상 행동으로 수행합니다. 모델 시간과 실제 사람의 플레이 시간을 구분합니다. 개발 서버 실행 중 `node scripts/boss-gallery.mjs`는 12보스 외형 검토 화면을 저장합니다.

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH = "$PWD\.cache\ms-playwright"
npx playwright install chromium
$env:PLAYWRIGHT_CHANNEL = 'chromium'
npm run test:browser
```

설치된 Edge를 사용할 때는 `$env:PLAYWRIGHT_CHANNEL = 'msedge'`를 설정할 수 있습니다. Edge와 다운로드한 Chromium의 실제 플레이 검증은 이번 작업에서 별도로 수행하지 않았습니다. 브라우저 설치·실행 방법은 [Playwright 공식 문서](https://playwright.dev/docs/intro)를 확인했습니다.

브라우저 테스트는 실제 버튼·3D 타일 레이캐스팅·키보드 입력을 사용합니다. 반복 시간을 줄이기 위해 Playwright의 브라우저 가상 시계로 정상 애니메이션 프레임을 진행하며 게임 상태를 주입하지 않습니다. 실시간 측정은 별도로 수행합니다.

Playwright 검증은 순서대로 실행하세요. 같은 결과 폴더를 사용하는 여러 실행은 서로 추적 파일을 삭제할 수 있습니다. 별도 실행이 필요하면 `--output artifacts/별도결과 --reporter=line`으로 결과 폴더를 분리합니다. 게임 소스·공개 에셋 변경은 브라우저 검증을 시작하기 전에 마칩니다.
전체 브라우저 명령은 안내·WASD/IME·성장·함대 지휘/개장/자동 사격·적 AI·수호자·기지 방어/공략·탐험/해도·저장/복구의 **105개 흐름**을 실행합니다. 현재 게임의 동결105개 전체 통과와 별도267규칙 통과를 `CAMPAIGN_VALIDATION.md`에 기록했습니다. `npm run test:rts`는 정상 획득 저장을 생성한 뒤 함대/방어/기지 공략 흐름을 검증합니다. `npm run audit:defense`와 `npm run audit:siege`는 정상 섬으로 각36작전의 비용과 결과를 기록합니다. `npm run audit:exploration`은24탐험의 정상 비용·전투·조사·결과 저장을, `npm run test:exploration`은 A/B 탐험·귀환·저장·포기와 잘못된 기록 불러오기 UI를 검사합니다. `npm run audit:journey`는 새로운 섬 하나로 캠페인과 모든 외해192작전을 연속 진행하며 `artifacts/journey-audit.json`에 같은 자원·연구·생존 함대의 진행 결과를 남깁니다. 생산 시설만 검증할 때는 먼저 `npm run audit:colony`로 정상 획득 저장을 생성한 뒤 `npx playwright test tests/browser/production.spec.js`를 실행하세요. `audit:colony`는 네 종류 생산/연구 시설을 무장·방호·공방과 함께 건설하고 수확·연구·배치·강화로72원정을 진행하며 `artifacts/campaign-audit-colony.json`과 해역별 정박지 저장을 기록합니다.

연속 공략에 `--support-guard --fleet-refits --fleet-priorities`를 추가하면 정상 유료 개장·지원 호위와 요격정 가까운 적/포격정 지원 적/잠수정 장갑 적 설정을 사용하는 자동 전략을 비교할 수 있습니다. `--output=artifacts/새결과폴더`로 기존 기록과 분리하세요. 같은 규칙의 자동 공략이며 사람의 재미·20시간 품질을 대신하지 않습니다. 실제 시간 비교는 재개한 작전의 관측 시간을 보존하고 부분 시간과 전체 시간을 구분합니다.

```powershell

node scripts/browser-metrics.mjs
# 빌드 미리보기 실행 중, 실제 시간의 첫 원정/최종 수호자 표본
```

기존 훈련 검증 결과는 `VALIDATION.md`, 신규 캠페인 검증은 `CAMPAIGN_VALIDATION.md`에 기록합니다. 스크린샷·측정 자료는 `artifacts/`, HTML 테스트 보고서는 `playwright-report/`에 생성됩니다. 기본 Windows 샌드박스의 프로세스 생성 또는 루프백 소켓 접근 제한은 승인된 프로젝트 명령 실행으로 해소했습니다. 게임의 실행 요구 사항을 추가하는 제한이 아닙니다.

## 범위와 알려진 제한

탐험에서 귀환한 기록은 오른쪽 **기록** 탭에 해역별 지도와 회수품으로 남습니다. 일부 지점만 조사하고 돌아와도 다음 원정에서 빠진 곳을 채워 해도를 완성할 수 있으며 완성 보상은 한 번 지급합니다. 완성 해도1개/4개로 **항로 측량** 연구1/2단계를 열어 연구소 표본·어획·작물 생산을 개선합니다. 이전 전체 탐험 저장은 완성 해도로 복원하고, 이전 부분 탐험은 남아 있는 조사 수와 필수 지점만 복원합니다.

`npm run audit:atlas`는 정상 획득한 섬에서 부분 귀환→재탐사→중복 보상 차단→실제 비용의 연구까지 모델로 검사합니다. `npm run test:atlas`는 이 저장을 생성한 뒤 지도·회수품·재탐사·연구·기존 저장 호환성과 손상 파일 거부를 UI로 확인합니다. PC 파일 저장·렌더링·음향·함대 도착·전대 편성·특수 공략과 검사기 비교 회귀를 포함한 최신 규칙 검사는157개이며 실제 실행 결과와 범위는 `CAMPAIGN_VALIDATION.md`에 기록합니다.

세 전투 훈련과 지속 진행 캠페인 개발판을 제공합니다. 조선소에서 함대를 생산하고 선택·이동·공격할 수 있습니다. 온라인 PvP와 유료 경제는 없습니다. PC가 기준이며 모바일용 터치 이동은 없습니다. 수면은 시각 효과이며 부력 시뮬레이션은 없습니다. 포탄은 발사 순간 피해를 계산하고 비행·폭발로 표현합니다. 보스 경고 공격은 예고가 끝난 시점의 실제 위치를 검사하므로 이동으로 회피할 수 있습니다. 적은 섬·함대·일부 임무의 동맹 정박지에 피해를 주며, 기지 방어 작전에서는 성벽과 개별 시설도 파괴됩니다. 파괴된 시설은 유료 복구가 필요합니다.

빌드 시 Three.js 포함 JavaScript 번들의 500 kB 경고가 표시됩니다. 빌드는 성공합니다. 외부 네트워크에서 모델·폰트·텍스처·음향을 로드하지 않습니다. WebGL 초기화 실패 시 실행 제한 안내를 보여줍니다. WebGL 비활성 환경, 다른 GPU·브라우저와 실제 저사양 기기의 성능은 확인 범위 밖입니다. 캠페인의 최종 분량·반복성·경제·난이도 조정과 장시간 검증은 남아 있습니다.


## 농장과 타일 면 성벽

수경 농장은 첫 해역부터 건설할 수 있습니다(자원150·전력1). 원정 목표3개를 확보하면 작물을 생산하며 시설을 선택해 수확·강화합니다. 어업장·크레인·연구소와 함께 생산 구성을 선택할 수 있습니다.

섬 정비에서 **방호 성벽**을 선택하고 배치도의 타일 테두리를 클릭하세요. 북·동·남·서 버튼을 고른 뒤 타일 안쪽을 클릭해도 됩니다. 3D 화면에서는 타일의 설치할 면 가까이를 클릭합니다. 한 타일에 농장/포탑과 네 면 성벽을 함께 배치할 수 있습니다. 같은 경계는 이웃 타일에서도 하나의 성벽으로 표시합니다. 기존 성벽을 클릭하면 강화·무료 재배치·철거·손상 복구를 선택합니다. 이전 저장의 성벽은 같은 타일의 북쪽 면으로 이동하고 내구도·강화·투자액을 보존합니다.

`npx playwright test tests/browser/walls.spec.js`는 첫 농장 생산과 면 성벽 배치·저장·기존 저장 호환성을 확인합니다. 새 게임과 보관된 정상 획득 호환성 저장을 사용하므로 별도 모델 실행이 필요하지 않습니다. `node scripts/audit-walls.mjs`는 새 섬의 첫 농장 원정·수확·두 면 성벽 건설을 정상 행동으로 모델 검증합니다.


Playwright는 테스트 전용 `http://127.0.0.1:5187` 서버를 직접 시작하고 종료합니다. 다른 프로젝트의5173 서버를 재사용하지 않습니다. 테스트 포트를 변경해야 하면 `TIDEHOLD_TEST_PORT`를 지정하세요. 로컬 실행 빌드의4173 서버는 그대로 사용합니다.

## 대규모 섬 렌더링

전투와 이동은 기존 시뮬레이션 속도를 유지합니다. 일시정지·시작/결과 화면은 초당15회만 그리며 숨겨진 창은 그리지 않습니다. 반복되는 타일·성벽 장식과 수면의 작은 물거품은 외형과 클릭 영역을 유지하며 묶어 그립니다. 변경되지 않은 음량/정지 상태의 오디오 설정도 프레임마다 반복하지 않습니다.

`node scripts/render-lifecycle-check.mjs`는 자체5189 개발 서버와 별도 Chrome에서 정상 획득한 후반 섬을 실제 비용으로 재편해53시설·19함대의 방어/기지 공략/탐험을12회 전환합니다. 읽기 전용 개발 진단과 진단용 GC로 같은 정박지의 그래픽 자원·보존 메모리·정지 화면 작업 시간·짧은 프레임 표본을 확인합니다. 게임 상태나 시계를 주입하지 않으며 사용자 저장을 건드리지 않습니다. 이 약3분 검사를 장시간/다른 GPU 성능 검증으로 간주하지 않습니다.

## 실제 시간의 장시간 검사

`node scripts/live-journey.mjs --output=artifacts/live-run-새이름`은 새 섬부터 현재192개 콘텐츠를 실제 시간과 일반 UI로 진행하므로 여러 시간이 걸립니다. `--limit=1 --port=5191`은 첫 임무만 확인하는 예비 실행입니다. 출력 폴더는 새 이름이어야 하고 기존 실행을 덮어쓰지 않습니다. 게임/검사 코드 복사와 해시·별도 Chrome 프로필·전용5192 서버를 사용하며 현재 사용자 서버/저장과 분리합니다. 개발 진단은 읽기 전용이며 자원·체력·시간·위치를 주입하지 않습니다. `live-audit.json`에 실제 경과시간, 항해 시간, 저장 내보내기, 그래픽 자원/렌더러 힙 표본, 실패와 완료 상태를 기록합니다. 개발판의 자동 플레이이며 사람의 재미/20시간 플레이/출시 품질 판정을 대신하지 않습니다.

`--resume --output=기존검사폴더`는 종료가 확인된 자체 프로필과 완료 내보내기만 사용합니다. 프로필에 이미 이긴 결과가 있으면 정상 이어하기·귀환·공개 내보내기로 보존하고, 다음 작전의 정지된 활성 저장이면 완료 순서·작전·비용·자동 저장 시간 범위를 대조한 뒤 정상 이어하기로 계속합니다. 해당 활성 저장의 앞부분 실제 소요 시간과 이후 구간을 합쳐 하나의 정확한 임무 시간으로 꾸미지 않습니다. 그 외에는 검증된 완료 내보내기를 공개 UI로 불러옵니다. 고정 게임 버전과 이전 실패 저널/검사 코드·가져오기 횟수·구간/해시를 보존하며, 재개는 중단 없는 단일 실행의 증거가 아닙니다. 실행 중 저널 또는 살아 있는 프로세스를 시간 초과만으로 재시작하지 마세요. 이전168개 고정 버전과 새192개 고정 버전은 별도 범위입니다.

## 엔딩 이후 특수 기지

마지막 이야기와 해역의 기존 세 기지 공략을 완료하면 **잔존 송전망 → 선단의 세 도크**가 열립니다. 12해역에 두 작전씩24개가 추가되어, 이야기72·방어36·함대 공략60·탐험24의 총192개 작전입니다. 엔딩 이후 특수 기지는 마지막 해역의 전투 수준을 사용합니다.

해역마다 발전기 거리, 도크 폭, 성벽 진입로와 수비대 위치가 다릅니다. 산호 해역 이후에는 **금빛 공급선과 청록빛 공급선**이 각각 한 측면의 포탑과 도크를 공급하고 중앙 지휘핵은 양쪽 전력을 받습니다. 한 발전기를 파괴하면 해당 측면의 방호·포탑 강화가 먼저 끊깁니다. 이전 저장의 전역 송전망은 그대로 유지합니다. 호위·사수는 이미 교전 중인 적에 반응하며 직접 공격·공격 이동은 새 적을 공격할 수 있습니다.

화면에는 살아 있는 지휘핵의 전력을 `서 1 · 중앙 2 · 동 1`처럼 표시합니다. 서부 발전기를 파괴하면 `서 0 · 중앙 1 · 동 1`이 됩니다. 전력0인 핵은 추가 장갑과 자동 수리 공급이 사라지며, 중앙1은 다른 발전기가 여전히 공급한다는 뜻입니다. 큰 제목은 현재 임무/작전 이름을 보여주고 정박지에서 기본 제목으로 돌아갑니다.

밝은 선으로 연결된 원격 동력기는 거리와 관계없이 같은 기지의 포탑 화력과 지휘핵 방호를 공급합니다. 외곽으로 함대를 보내 동력기를 끊거나, 전대5–9를 나누어 양쪽을 공격하세요. 세 도크는 지휘핵 세 곳을 모두 파괴해야 확보하며, 남은 수비대가 항복하면 회수하지 않은 창고 보상은 받지 않습니다. 공세 사이 정비·유료 함대 생산/강화·진행 중 저장·출항 전 상태로 포기는 기존과 같습니다.

## 전대 편성

함대 탭에서 배를 클릭·Shift 추가 선택한 뒤 **Ctrl+5–9**로 전대에 등록하세요. **5–9**로 즉시 선택하고 같은 번호를 연속 두 번 누르면 해당 함대를 따라 봅니다. **Shift+숫자**는 현재 선택에 추가, **Ctrl+Shift+숫자**는 기존 편성에 함선을 추가합니다. 각 전대의 **등록** 버튼으로도 편성할 수 있습니다. 선택 없이 Ctrl+숫자를 누르면 그 편성을 비웁니다. 능력은 기존 **1–4**번을 사용합니다.

편성은 자동 저장·내보내기·Windows PC 파일에 포함됩니다. 잃거나 해제한 함선은 선택되지 않고 새 함선이 그 자리를 자동으로 대신하지 않습니다. 출항/새 해역에도 유지하며 포기·재시도는 출항 전 함대와 편성으로 복구합니다. 이전 저장은 전대 등록 없이 그대로 이어갈 수 있습니다.

`npx playwright test tests/browser/fleet-groups.spec.js`는 정상 획득 저장에서 조선소/함선을 실제 결제한 뒤 두 이동 방식의 편성·별도 명령·단축키·저장 복원을 확인합니다. `node scripts/fleet-groups-check.mjs`는 최신4173 정적 빌드에서 실제5초 자동 저장과 재접속을 검사합니다. Windows 실행판은 `node scripts/fleet-groups-check.mjs --executable=<desktop-package.json의 executable>`로 별도 숨겨진 프로필에서 실제 종료·캐시 소실·파일 복구·전대 선택을 확인합니다. 검사 결과는 `artifacts/groups-*-production.json`이며 개인 저장은 열지 않습니다.
